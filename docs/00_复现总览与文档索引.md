### GitHub与VS Code日常操作

公开仓库：`https://github.com/liberty-joy/Go2W-RobotDog-Simulation`。VS Code打开`RobotDog.code-workspace`后，在“源代码管理”中填写提交消息、点击“提交”，再点“同步更改”或“推送”即可；SSH密钥由本机系统Git使用，不需要输入GitHub密码。

```bash
cd /home/joy/桌面/RobotDog
git status                         # 修改、暂存和分支状态
git diff                           # 查看尚未暂存的修改
git add 路径                       # 只暂存指定文件；慎用 git add .
git commit -m '简明说明本次改动'    # 创建本地提交
git pull --ff-only                 # 推送前只做快进拉取，不自动制造合并提交
git push                           # 推送当前main到origin/main
git log --oneline --decorate -10   # 查看最近提交
git restore --staged 路径          # 误暂存时撤出暂存区，不删除工作文件
```

不要提交`outputs/`、`models/`、`sim/assets/sensors/vendor/`、MCAP、权重或本机私钥。首次向新分支推送可用`git push -u origin 分支名`。多人协作或实验性修改先用`git switch -c feature/短名称`创建分支；普通工作禁止force push。

## 2. 从命令行复现阶段 0

使用普通用户终端；不需要 sudo、安装驱动或重新安装 Isaac。以下检查只在 localhost 的独立 ROS 域中运行单个仿真机器人。不要同时在同一域启动多个仿真。不会连接实机。

```bash
cd /home/joy/桌面/RobotDog
export ROS_DOMAIN_ID=97
export ROS_LOCALHOST_ONLY=1
RUN="/home/joy/桌面/RobotDog/outputs/sensor_pipeline/stage0_$(TZ=Asia/Shanghai date +%Y%m%dT%H%M%S)"
mkdir -p "$RUN"

# 只读盘点；目标目录必须是新目录。
/usr/bin/python3 scripts/sensor_pipeline/inventory.py --out "$RUN/inventory"

# 复用已有跨进程检查：位移、超时停车、RGB、内参、关节、TF、clock。
ROBOTDOG_REQUIRE_SINGLE_SIM=1 ROBOTDOG_OUTPUT_DIR="$RUN/headless_recheck" \
  ./scripts/ros2/test_bridge.sh \
  --policy outputs/training/wheel_slope/policy_jit.pt \
  > "$RUN/headless_recheck_runner.log" 2>&1

# 单机器人静止采集；30 秒可靠 RGB MCAP 样本、TF/时间戳与站姿检查。
./scripts/sensor_pipeline/run_capture.sh "$RUN/headless_reliable" headless \
  > "$RUN/headless_reliable_runner.log" 2>&1

# 可选 GUI 进程/渲染链路检查，要求 DISPLAY；自动退出，不等于人工按键验收。
./scripts/sensor_pipeline/run_capture.sh "$RUN/gui_capture" gui \
  > "$RUN/gui_capture_runner.log" 2>&1

# 从此次 JSON/MCAP 元数据重新计算验收表、预算与图表；不重新仿真。
/usr/bin/python3 scripts/sensor_pipeline/summarize.py --run "$RUN"
```

每次使用新 `RUN`，失败目录也保留。`run_capture.sh` 拒绝覆盖已有输出目录。回退采集 QoS 时不改变系统配置：普通启动不加 `--ros-image-reliable` 就仍使用原来的 best-effort RGB；配套订阅端 QoS 必须兼容。

结果位置：`headless_recheck/verification.json` 是原检查结果；`headless_reliable/probe.json` 是详细链路检查；`rgb.png` 为原始 RGB 样图；`info.json`、`static.json`、`tf.json` 为内参和坐标链；`stability.json` 为时序状态；`bag/` 为 MCAP、`bag_info.txt` 为录包统计；`resources.log` 记录显存/进程内存。顶层汇总文件由 `summarize.py` 生成。GUI 未运行时汇总明确记为未测试。

MCAP 是原始样本，保持在 Linux 本地。其时间从仿真零点计数，显示 1970 年并非主机时钟错误。运行日期在 run 元数据与日志中。RGB 头时间目前由发布时刻生成，不能据此声称已验证曝光同步。
