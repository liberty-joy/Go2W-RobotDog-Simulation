# Go2W 键盘轮式控制与前置相机

> 文档导航：编号与复现入口见 [00_复现总览与文档索引](00_复现总览与文档索引.md)。本文保留历史记录或规划，不代表本次复验结果；本次结果以 [阶段0环境验收](sensor_pipeline/00_environment.md) 为准。

启动前保存已有场景。此程序另建场景，读取本地机器人模型，在内存中保持站姿并设置轮速驱动，不覆盖原始 USD。请关闭不再使用的 Isaac Sim 窗口以释放显存。

在终端运行：

```bash
cd /home/joy/桌面/RobotDog
./scripts/run_go2w.sh
```

等待机器人加载并站稳，点击视口空白处获得键盘焦点（不要在文本输入框中操作）。

| 按键 | 功能 |
|---|---|
| W / S | 前进 / 后退 |
| A / D | 原地左转 / 右转 |
| W+A / W+D | 边走边转 |
| 松开按键 | 轮速目标归零 |
| 空格 | 清除行驶按键，零速度制动 |
| C | 前置摄像头与外部观察视角切换 |
| P | 保存当前前置 RGB 图片 |
| R | 恢复初始站姿并清零机身、关节和轮速 |

图片存放在 `/home/joy/桌面/RobotDog/outputs/camera/`，640×480，PNG 格式。终端打印每张图片的完整路径。相机随机身 base 刚体运动，近裁剪面 2cm，远裁剪面 100m。`Camera.get_rgb()` 返回 RGB 数组；程序在初始化后持续渲染，按 P 时读取并保存。

不加载策略时，轮速控制来自前进/转向指令的差速映射：腿部保持站立角度，四个轮子使用零刚度、非零阻尼的速度驱动。有效轮速映射尺度暂用 0.05m、半轮距暂用 0.18m，不能把它当作实机规格；实际机身速度受接触、摩擦和腿部姿态影响，尚未完成运动学标定。该固定站姿演示本身不是步态或实机控制。后续已加入 ROS 2 RGB/CameraInfo/TF/clock 发布和可选策略，见 [21_ROS2操作](21_Go2W_ROS2接入与训练操作.md)、[32_模式切换](32_Go2W鲁棒训练与模式切换验收.md)；本次实际复验见阶段 0 记录。

场景内加入红、蓝方块作为图像和移动的参照，方块带静态碰撞。先低速测试，切换到其他窗口前先松开移动键或按空格。

无窗口功能检查：

```bash
./scripts/run_go2w.sh --headless --test
```

连续三轮运行，每轮检查静止站立、前进、转向、RGB 图像保存，轮间执行停止、播放和完整复位。测试图像为 `outputs/camera/test_front.png`；自动测试通过不代表键盘窗口焦点与按键事件已经人工验证。

## 本机验证结果

2026-10-25：900 步测试完成，站立、前进位移、转向响应、包含彩色参照物的 RGB 图像均通过（日志 `outputs/go2w-teleop-test.log`）。相机安装俯角现为相对机身 5°，水平视野 80°（焦距 18mm），用于修正站姿恢复水平后画面过度朝地的问题。当前仅验证了仿真控制与图像链路，键盘焦点交互需要在图形窗口中实际使用确认。

## 站姿与重复播放修复

腿部目标：hip 0°、thigh 45°、calf -90°。腿部 angular drive 使用 force 模式，Stiffness 4、Damping 0.14（USD 角度单位为度，约等效 229 N·m/rad、8 N·m·s/rad）。保留 URDF 力矩上限：髋/大腿 23.7 N·m、小腿 35.55 N·m。轮子仍使用速度驱动。求解迭代设为位置 32、速度 4。

停止再播放时重新初始化站立姿态、机身位置和所有速度；暂停再继续保持当前状态。按 R 也可以手动复位。更新脚本后需要关闭旧演示进程，并用上述命令重新启动，已运行的窗口不会自动读取修改。

修复后实测：三轮各 900 步，共 2700 步；全部通过。每轮结束机身高度约 0.389m、横滚 0.026°、俯仰 -0.466°、腿部最大目标误差 2.243°。日志：`outputs/go2w-stability-test.log`。这覆盖平地低速演示，尚未验证复杂地形或外力冲击。

相机设置在每次 R 复位及停止后重播时恢复。相机仍跟随机身运动，不包含云台稳像。修改只作用于脚本创建的场景，需重新启动演示。
