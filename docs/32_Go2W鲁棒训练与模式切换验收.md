# Go2W 鲁棒训练与模式切换

> 文档导航：编号与复现入口见 [00_复现总览与文档索引](00_复现总览与文档索引.md)。本文保留历史记录或规划，不代表本次复验结果；本次结果以 [阶段0环境验收](sensor_pipeline/00_environment.md) 为准。

## 停车评估修正

原来的 10 项连续测试时长为 60 秒，但环境最大回合时长仍为 12 秒。周期性超时重置会把机器人重新放到 0.42m 高度，并带来速度尖峰。原报告中的最后停车 9/10 结果混入了重置影响，不能作为停车失败的依据；旧 JSON 和对比图仅作历史记录。

现在评估最大回合时长按完整测试序列计算，另外记录 `timeout_resets`。修正后的完整测试结果为 `outputs/training/wheel_stop_verified/suite.json`：10/10 通过，提前重置和超时重置均为零，最后停车峰值 0.00760m/s。

控制器在指令接近零时，按 `clamp((|vx|+0.18|wz|)/0.05,0,1)` 缩放动作残差，零指令恢复站姿并停止轮速。训练和运行使用同一个规则。它是控制器设计的一部分，不应描述为神经网络自主学会制动。`--raw-residuals` 可关闭训练/评估中的残差缩放，进行消融对照。

## 逐阶段训练

每阶段继承上一阶段权重，原权重保留：

1. `wheel_friction`：轮子静摩擦系数从 0.4–1.0、动摩擦从 0.35–0.9 采样，限制动摩擦不大于静摩擦；32 个材质桶，启动时随机分配到轮子碰撞体。
2. `wheel_push`：保留摩擦随机化，每 6 秒给机身 X/Y 速度分别叠加 ±0.08m/s 内的随机变化。第一次在第 3 秒触发。这是速度冲量模拟，不是指定牛顿数的外力。
3. `wheel_slope`：保留摩擦与扰动，加入绕世界 Y 轴旋转 3° 的刚性坡面。坡面长宽各 8m，环境间距 10m，机身高度按坡面局部高度修正。

训练开关：`--friction`、`--push 0.08`、`--slope 3`。同样可用于 `--evaluate-suite`。

三个阶段各 100 轮、256 环境，每轮 24 步，共新增 1,843,200 条环境转移。新轮腿权重为 `outputs/training/wheel_slope/model_final.pt`，运行导出为同目录 `policy_jit.pt` 和 `policy_jit.json`。

已完成的分项结果如下，每种条件均为 8 环境、10 项连续指令、每项 6 秒仿真时间、种子 42：

| 条件 | 通过 | 平均平面速度误差 m/s | 平均转向误差 rad/s | 最小地形相对机身高度 m |
|---|---|---|---|---|
| 平地 | 10/10 | 0.01158 | 0.04146 | 0.37864 |
| 摩擦变化 | 10/10 | 0.01338 | 0.04377 | 0.37946 |
| 摩擦 + 扰动 | 10/10 | 0.01378 | 0.04415 | 0.37797 |
| 摩擦 + 扰动 + 3° 坡面 | 10/10 | 0.01737 | 0.05935 | 0.37817 |
| 摩擦 + 扰动 − 3° 坡面 | 10/10 | 0.02259 | 0.04806 | 0.38025 |

上述检查均无提前重置或超时重置。带扰动的每种条件共实际触发 80 次环境级速度冲量。报告为 `outputs/training/wheel_verified_*/suite.json`，汇总为 `outputs/training/robustness_summary.json`，图表为 `outputs/training/go2w_robustness.png`。

坡面初次配置误用了旧的四元数顺序，相关权重已保留在 `wheel_slope_old_orientation`，早期 `wheel_robust_*` 报告不用于验收。当前配置使用 Isaac Lab 3 的 `(x,y,z,w)`，并在物理启动后验证 USD 坡面实际法向；上表仅使用修正后重训权重和 `wheel_verified_*` 结果。当前验证范围为低速、小扰动、±3° 平面和单一种子，未包含台阶、崎岖地形或实机。

有扰动时，停车验收使用每项最后 1 秒的峰值速度，要求 <0.05m/s；它检验扰动后的恢复。整个统计区间的峰值仍保存在报告中。无扰动时，停车继续使用切换 1 秒后的整个区间峰值。其余跟踪与姿态阈值相同。

## 纯腿训练

`--mode walk` 使用 12 维关节动作、54 维观测。轮关节使用位置保持，腿部以对角相位的 1.5Hz 足端轨迹为参考，二连杆逆运动学生成关节目标，策略输出残差。步幅随前进和转向指令变化，参考摆动净空 0.05m。导出契约标明 `gait_reference=ik_v1`。

完整纯腿运动是否达标应看实际分项评估，不能用“模型已导出”或“能保持站立”代替步态验收。

## 仿真中的切换入口

同时提供两份策略后启动：

```bash
./scripts/run_go2w_ros2.sh \
  --policy outputs/training/wheel_slope/policy_jit.pt \
  --walk-policy outputs/training/walk_clearance/policy_jit.pt
```

先停止旧仿真，避免同一 ROS 域中有多个机器人发布相同话题。默认进入 wheel。键盘 M 请求切换；或者 ROS 发布：

也可以使用组合启动脚本 `./scripts/run_go2w_dual.sh`，加载上述两份策略。

```bash
source scripts/ros2/env.sh
ros2 topic pub --once /go2w/control_mode/cmd std_msgs/msg/String "{data: walk}"
ros2 topic echo /go2w/control_mode
```

切回时把 `walk` 换成 `wheel`。切换要求指令归零、平移速度 <0.03m/s、角速度范数 <0.08rad/s，并连续保持 0.5 秒；不满足则拒绝本次请求，需要停车后重新发送。纯腿模式运行速度限制为 ±0.10m/s、转向 ±0.20rad/s。

进入纯腿模式会锁定当前轮子角度，进入轮式模式会恢复轮子速度控制；不瞬间把已经转过的轮子角度拉回零。重置时清除策略状态并重新配置执行器。

`scripts/ros2/test_modes.sh` 验证运动中拒绝切换、静止切换、纯腿低速直行、停车和切回。完整转向效果另由纯腿分项评估检查；该 ROS 检查不覆盖纯腿坡面和复杂地形。

选定组合的上述 8 项 ROS 检查全部通过，结果为 `outputs/ros2/mode-verification-selected.json`。直行检查验证正向位移、姿态与停车，不验证稳态速度精度。轮腿 ROS 相机、TF、关节、时钟和超时制动等 8 项联调检查也全部通过，结果为 `outputs/ros2/verification-robust-policy.json`。策略选用记录为 `outputs/training/controller_selection.json`。

## 纯腿评估的边界

**当前组合启动脚本选择 `walk_clearance`（累计 900 轮），保持实验性标记。** 它在 ±0.10m/s、±0.20rad/s 下的速度/姿态跟踪 10/10 通过，平均平面速度误差 0.01474m/s、平均转向误差 0.03487rad/s，无提前重置或超时重置。但足端曲线显示抬升不对称，尤其后腿净空不足，完整四足步态尚未通过。图为 `outputs/training/walk_clearance_suite/gait.png`。

`walk_bounded` 是额外 150 轮的候选实验，未提升为默认策略，因为收紧残差后转向跟踪退步，逐腿抬升也未全部达标。所有候选权重保留，不覆盖已验证策略。

累计训练经历 300 轮初始 IK 残差、300 轮转向强化、300 轮抬足强化，最后 150 轮收紧残差和加强高度约束，总计 1050 轮。此前较宽残差允许策略抵消参考抬足动作，出现前腿抬升、后腿贴地的挪动。最后阶段 `walk_bounded` 将残差缩放从 0.35 收紧到 0.12rad，并在契约中记录 `leg_action_scale`；运行端读取同一数值。

速度/姿态验收和步态抬足验收分别记录。`passed` 仍表示跟踪与稳定性达标；`gait_passed` 另外要求移动时轮心高于 0.106m 的总体比例 >10%，且四条腿各自的比例都 >5%。0.106m 来自官方轮子网格约 0.086m 的半径加 0.020m 净空。它是运动学抬足判据，不能替代接触力传感器或完整步态对称性评价。

复测最终纯腿权重：

```bash
./scripts/train_go2w.sh --headless --mode walk --evaluate-suite \
  --suite-speed .1 --suite-yaw .2 --walk-action-scale .12 \
  --checkpoint outputs/training/walk_bounded/model_final.pt \
  --num_envs 8 --steps 180 --log_dir outputs/training/walk_bounded_suite
```

旧 `walk_ik_initial`、`walk_ik_refined`、`walk_clearance` 使用 0.35rad 残差，如要重放这些训练控制器，应额外指定 `--walk-action-scale .35`。旧报告中的速度跟踪通过不等于四足步态通过。

复测组合启动脚本所用的纯腿策略：

```bash
./scripts/train_go2w.sh --headless --mode walk --evaluate-suite \
  --suite-speed .1 --suite-yaw .2 --walk-action-scale .35 \
  --checkpoint outputs/training/walk_clearance/model_final.pt \
  --num_envs 8 --steps 180 --log_dir outputs/training/walk_clearance_suite
```

下一步应针对逐腿摆动净空和支撑时序加入接触状态评价，校正参考轨迹与载荷分配；本次数据不支持把纯腿控制称为成熟四足步态，也未在纯腿模式上验收摩擦扰动和坡面。
